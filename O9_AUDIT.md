## Medium

**M1. A22 delay credits pre-tau detections (spec level).** `s5_a22.h1a_points_shifted` shifts every availability, so the sweep's hit test `T_d + delta > tau` turns detections whose decision bar is at or before tau (based on pre-change data only) into hits once `delta` moves them past tau. A real decision delay does not make a pre-change detection about the change. H1(c) under the delay shifts T_c only, which also admits confirmations up to delta minutes before the release. Implemented exactly as A22 rule 3d states. Effect: the delay results are biased toward robustness; observed H1(a) rises slightly with delay (Gaussian 0.105 / 0.107 / 0.108, HSMM 0.111 / 0.113 / 0.113) and the H1(c) difference rises (Gaussian +0.24 / +0.28 / +0.29), which this mechanism can produce. Fix needs an amendment: hit = unshifted T_d strictly after tau and T_c + delta within tau + 60 min.

**M2. Zero slot medians make __sadj values undefined on LEGACY bars.** `step11_a4_rerun_4_3_4_7_8.adjust` returns NaN where the causal median of the same slot over the previous 20 sessions is 0 (base > 0 required). In LEGACY 7-24% of 1-minute returns are exactly 0 (by year; 2004-2006 highest), so for r^2-type inputs the median is 0 whenever more than half of those 20 minutes were flat. This is the whole cause of the 47 D7 NaN-variance-ratio days (close-out item 3; 47/47, 1-5 bars per window). The same construction feeds every __sadj feature, the A8 splice scale (`in_units_of_A`) and D8/D8c. For the detector features themselves the zero median is minor: on LEGACY 5-minute grid bars it explains 0.24-0.52% (bars with a finite base value but a NaN __sadj value; RAW 1.4%). Most of their missingness comes from the base feature's own validity window: base NaN on LEGACY grid bars is rv10_partial90 14.9%, rv5_strict 10.5%, abs_return_1m 4.4%, intrabar_range_log 3.0% (RAW 0.2-2.9%). Sadj NaN totals on LEGACY grid bars: rv10_partial90__sadj 15.1%, downside10_strict 17.2%, rv5_strict / downside5_strict 10.7%, abs_return_1m 4.9%, intrabar_range_log 3.3% (`section5/results/o9/sadj_nan_attribution.txt`). Bars where a feature is NaN are not real updates for feature models, while the return-only baseline keeps them. So LEGACY feature models (rv10_partial90__sadj is the era final feature) update on about 15% fewer bars than their baselines. This holds in MR2 as run and in all its comparisons. It is a data-construction property, not a scoring bug, but it is undisclosed and it differs by era (RAW about 4%).

**M3. Grid sensitivity conflates resolution with event-rule timing (spec level, relevant to the 1-min contradiction).** The event rule is counted in updates (3 consecutive real updates, the first 2 silent; `s5_sweep` run = 3, warm = 2) and A22 rule 3g kept it unchanged: confirmation takes 2 minutes at 1 min, 10 at 5 min, 30 at 15 min. Taus stay on the 5-minute stamps (`s5_eval.TAU_SLOTS` = 94 + 5k), so at 15 minutes the first post-tau bar mixes pre- and post-change minutes, and the 60-minute hit window holds 4 bars. At 1 minute the H1(a) x-axis (null alarms per session, at most 0.5) is reached at much higher thresholds because 5x more updates give 5x more chances to alarm. The 1-min Gaussian H1(a) = -0.055 is therefore a statement about these setups and this rule at 1 minute, not about information content. No implementation error was found in the grid path (GRID / FIRST_SLOT, grid-width deseasonalising matrix, Dmax 390 / G, DM lag 60 / G, splices via `session_grid`).
